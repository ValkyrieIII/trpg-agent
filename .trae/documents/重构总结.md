# TRPG Agent 重构总结

## 一、已完成的工作

### 1. 核心 BUG 修复

#### 1.1 `process()` 返回值丢失（最严重）
- **问题**：`game_master.py` 的 `process()` 方法中，所有累积的叙述 `all_narrations` 只通过 `_stream_text()` 输出到 CLI，Web 模式下 `console=None` 导致叙述完全丢失。最终 `response = ""` 只返回了建议和世界事件。
- **修复**：正确构建完整响应 `self._render_accumulated(all_narrations, suggestions)`，包含叙述、建议、世界事件。

#### 1.2 存档加载方法名错误
- **问题**：`api_server.py` 调用 `gm.load()`，但实际方法是 `gm.load_save()`。
- **修复**：改为 `gm.load_save()`。

#### 1.3 存档加载不更新前端状态
- **问题**：`ModalSettings.tsx` 加载存档后，没有调用 `setPlayerState()` 和 `setNpcs()` 更新 Zustand store。
- **修复**：加载存档后正确更新所有前端状态。

#### 1.4 前端文本重复显示
- **问题**：SSE 流发送文本块 AND 最终 `narration` 字段，前端累积后再次添加导致重复。
- **修复**：后端不再发送 `narration` 字段，前端只使用累积的 `fullText` 作为消息。

### 2. 硬编码清除

#### 2.1 移除疯狂值系统
- **文件修改**：
  - `state.py`：完全删除 `madness`、`MAX_MADNESS`、`_MADNESS_THRESHOLDS`、`check_madness()`、`adjust_madness()` 等
  - `game_master.py`：移除 `madness_check` 工具、`_tool_madness_check` 方法、所有 madness 引用
  - `config.yaml`：删除 `madness: 5`
  - `StatePanel.tsx`：移除疯狂值显示条
  - `gameStore.ts`：`madness` 标记为可选（向后兼容旧存档）
  - `event.py`：删除（包含 `_resolve_madness_risk` 等疯狂相关逻辑）
  - `_GM_SYSTEM_PROMPT`：移除疯狂值/序列/魔药等硬编码机制描述

#### 2.2 世界观硬编码清除
- **问题**：GM System Prompt 硬编码"诡秘之主"世界观，config.yaml 固定为贝克兰德/第五纪。
- **修复**：
  - GM prompt 使用 `{world_setting}` 占位符，动态注入
  - `config.yaml` 改为通用模板（"自定义世界"）
  - 用户输入的 `worldview` 直接更新 `gm.world["description"]`，影响后续所有游戏流程

#### 2.3 NPC 属性动态生成
- **问题**：所有 NPC 创建点（`_tool_create_npc`、`_register_backstory_npcs`、`generate_opening`）都使用硬编码的 `10/10/10/10/10/10` 属性。
- **修复**：新增 `_generate_npc_attributes()` 方法，通过 LLM 根据角色描述生成独特属性（1-20 范围）。

#### 2.4 世界状态初始化
- **问题**：`_time_of_day = "黄昏"`、`_weather = "阴"` 硬编码。
- **修复**：改为 `"未知"`，由 GM 在开场时通过 `set_scene` 工具自动设置。

### 3. 前端改进

#### 3.1 自定义世界观/NPC 输入界面
- `StartScreen.tsx` 添加了世界观和初始 NPC 的 textarea 输入框
- 参数通过 `/api/start` 传递给后端

#### 3.2 状态面板通用化
- `StatePanel.tsx` 重写为只显示 HP、情绪、体力、信任
- 移除所有疯狂值相关显示
- 接收 `playerState` 和 `npcs` 作为 props

#### 3.3 前端构建成功
- `npm run build` 通过，无 TypeScript 错误

### 4. 后端改进

#### 4.1 `/api/start` 端点
- 接收 `worldview` 和 `npc_setup` 参数
- 自定义世界观更新 GM 的 `self.world["description"]`，影响后续所有 `process()` 调用

#### 4.2 `generate_opening()` 方法
- 支持 `custom_worldview` 和 `custom_npc_setup` 参数
- 同步更新 `self.world` 状态

#### 4.3 GM System Prompt 重写
- 完全通用的 TRPG prompt，不绑定任何特定世界观
- 世界设定通过 `{world_setting}` 动态注入
- 移除疯狂值、序列、魔药、扮演法等硬编码机制
- 添加 `{player_name}` 占位符替换（之前遗漏）

## 二、数据流链路（已验证）

```
StartScreen.tsx
  ├─ worldview / npc_setup → POST /api/start
  │   └─ gm.world["description"] 更新
  │       └─ generate_opening() → opening + suggestions + state + npcs
  │           └─ addMessage('gm', data.opening)
  │           └─ setSuggestions(data.suggestions)
  │           └─ setPlayerState(data.state)
  │           └─ setNpcs(data.npcs)
  └─ setGameStarted(true) → GameInterface

GameInterface.tsx
  ├─ sendAction(action) → POST /api/action (SSE)
  │   └─ gm.process(action) → fullText (SSE chunks)
  │       └─ addMessage('gm', fullText)
  │       └─ setSuggestions(finalData.suggestions)
  │       └─ setPlayerState(finalData.state)
  │       └─ setNpcs(finalData.npcs)
  └─ suggestions 按钮 → sendAction(suggestion)

ModalSettings.tsx
  ├─ POST /api/save → gm.save()
  └─ POST /api/load → gm.load_save() → setPlayerState + setNpcs
```

## 三、有待改善的领域

### 1. 中等优先级

| 问题 | 说明 |
|------|------|
| **角色卡自定义** | config.yaml 仍是通用模板，开场前应有完整的角色创建界面（名称、属性、技能、背景） |
| **事件文件删除** | `event.py` 已删除，但可能有其他模块引用它（需要检查） |
| **旧存档兼容** | 旧存档包含 `madness` 字段，`StateMachine.from_dict()` 不再接受该参数，加载可能报错 |
| **NPC 人格模板** | `_generate_npc_attributes` 的 fallback 仍是统一的 10/10/10，LLM 不可用时所有 NPC 属性相同 |
| **世界模拟触发** | `_maybe_trigger_world_simulation()` 仍是每 3 回合固定触发，没有基于时间/剧情变化 |

### 2. 低优先级

| 问题 | 说明 |
|------|------|
| **CLI 终端支持** | `main.py` CLI 入口可能仍有 madness 相关引用 |
| **知识库文件** | `config.yaml` 引用 `data/knowledge` 目录，但目录可能不存在或内容为空 |
| **前端错误处理** | SSE 连接断开时的重试机制缺失 |
| **移动端适配** | 前端布局在窄屏上可能显示异常 |
| **世界构建命令** | `!world`、`!npc` 等命令的 Web 界面集成不完整 |

### 3. 架构层面

| 问题 | 说明 |
|------|------|
| **单一 GameMaster 实例** | `_gm` 是全局单例，多用户同时使用会互相干扰 |
| **存档格式** | JSON 存档没有版本控制，未来修改可能导致不兼容 |
| **LLM 超时** | 没有设置 LLM 请求超时时间，慢请求可能阻塞 |
| **NPC Agent** | 原计划的"每个重要 NPC 配一个 Agent"尚未实现 |
