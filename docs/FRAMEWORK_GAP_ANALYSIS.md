# TRPG Agent vs 成熟 Agent 框架 — 差距分析

> 2026-07-17 | 对比对象：LangGraph、CrewAI、AutoGen、OpenAI Agents SDK（原生用法）

---

## 总体评估

TRPG Agent 的核心 Agent 循环（编排者 + 工具调用 + 多 Agent NPC）已经跑通，属于 **可用原型** 阶段。与成熟的 Agent 框架相比，主要在以下维度存在差距：

---

## 1. Agent 编排与生命周期

| 能力 | 当前状态 | 差距 |
|------|---------|------|
| **Agent 间 Handoff** | ❌ 无 | NPC 作为工具被调用，非真正的控制权转移。GM 无法将主导权交给 NPC Agent |
| **Agent 生命周期管理** | ⚠️ 半成品 | NPC Agent 创建后无销毁机制、无健康检查、无闲置回收 |
| **并行 Agent 执行** | ❌ 无 | 多 NPC 对话串行处理，无法同时让多个 NPC 回应 |
| **Agent 角色定义** | ⚠️ 基础 | NPC 只有 personality_tone，无行为策略、目标驱动、禁忌列表 |
| **动态 Agent 池** | ⚠️ 基础 | NPC Agent 随 create_npc 创建，但无上限、无 LRU 淘汰 |
| **Agent 预热/初始化** | ❌ 无 | 无知识预加载、无角色卡预注入优化 |

**严重程度：中** — Handoff 在 TRPG 场景中不急需，但 NPC 并行执行能显著提升多 NPC 群聊体验。

---

## 2. 安全与护栏 (Guardrails)

| 能力 | 当前状态 | 差距 |
|------|---------|------|
| **输入安全** | ❌ 无 | 无 prompt injection 防护，用户输入直接进入 Agent 上下文 |
| **输出过滤** | ❌ 无 | 无有害内容检测，无敏感词过滤 |
| **输出格式校验** | ⚠️ 隐式 | 依赖 prompt 约束输出 JSON，无 schema 强制校验（SDK 有 structured output 但未使用） |
| **幻觉检测** | ❌ 无 | GM 可能编造世界观设定，虽然 prompt 要求先 search_knowledge 但不强制 |
| **工具调用护栏** | ❌ 无 | 无工具调用频率限制、无危险操作确认（如 game_over 会直接删档） |
| **成本控制** | ❌ 无 | 无 token 预算、无单次调用 token 上限 |
| **API Key 安全** | ⚠️ 基础 | Key 在 .env 明文存储，前端无鉴权可直连后端 API |

**严重程度：高** — game_over 工具无确认直接删档、后端 API 无鉴权直接暴露、无 token 预算可能导致费用失控。

---

## 3. 可观测性 (Observability)

| 能力 | 当前状态 | 差距 |
|------|---------|------|
| **Tracing / 链路追踪** | ❌ 无 | 无 OpenTelemetry 集成，无 LangSmith / Arize 等平台接入 |
| **Token 用量统计** | ❌ 无 | 无法知道每次对话消耗多少 token、花了多少钱 |
| **延迟监控** | ❌ 无 | 无各环节耗时统计（记忆检索、LLM 推理、工具调用） |
| **工具调用日志** | ⚠️ 基础 | debug_log 只有文本行，无结构化日志（JSON）、无时间戳 |
| **错误追踪** | ❌ 无 | 异常被简单 catch，无 Sentry 等错误上报 |
| **会话回放** | ❌ 无 | 无法回放某次对话的完整 Agent 决策过程 |
| **Dashboard** | ❌ 无 | 无可视化监控面板 |

**严重程度：中** — 调试靠 `--debug` 文本日志，排查问题效率低。Token 统计是刚需。

---

## 4. 错误处理与韧性

| 能力 | 当前状态 | 差距 |
|------|---------|------|
| **LLM 重试** | ❌ 无 | API 调用失败直接抛异常，无指数退避重试 |
| **降级策略** | ⚠️ 部分 | NPC Agent 失败降级到 legacy LLM.chat()，但 GM Agent 无降级 |
| **熔断器** | ❌ 无 | 连续失败无自动熔断 |
| **超时控制** | ❌ 无 | LLM 调用无超时限制 |
| **部分失败恢复** | ❌ 无 | 一个工具失败可能导致整轮响应丢失 |
| **并发限流** | ❌ 无 | 无请求队列、无并发限制 |

**严重程度：高** — 生产环境中 LLM API 不稳定是常态，缺少重试和超时会直接导致用户体验崩溃。

---

## 5. 评估与质量 (Evaluation)

| 能力 | 当前状态 | 差距 |
|------|---------|------|
| **单元测试** | ✅ 有 | 8 个测试文件覆盖骰子、角色、状态、检定等 |
| **Agent 行为测试** | ❌ 无 | 无法验证 "GM 是否正确处理了玩家输入" |
| **Golden Dataset** | ❌ 无 | 无标准输入-期望输出对 |
| **回归测试** | ❌ 无 | 改 prompt 后无自动验证 |
| **叙事质量评分** | ❌ 无 | 无自动化评估（连贯性、一致性、趣味性） |
| **工具选择准确性** | ❌ 无 | ToolAdvisor 存在但未系统评估其建议准确率 |
| **A/B 测试** | ❌ 无 | 无不同 prompt/模型的对比测试框架 |

**严重程度：中** — 改一行 prompt 可能破坏整体体验，但完全不知道。

---

## 6. 记忆与上下文管理

| 能力 | 当前状态 | 差距 |
|------|---------|------|
| **重要性自动评分** | ❌ 无 | importance 硬编码为 0.5，无 LLM 自动判断记忆重要性 |
| **记忆压缩/总结** | ❌ 无 | 记忆只增不减，长期游戏会膨胀 |
| **情节边界** | ❌ 无 | 无 "一个场景结束" 的标记，所有记忆混在一起 |
| **上下文窗口管理** | ⚠️ 基础 | history 截断到 5 轮，但无 token 级别的精确控制 |
| **工作记忆** | ❌ 无 | 无 scratchpad / working memory 概念，Agent 无法记录中间推理 |
| **层次化记忆** | ❌ 无 | 无 "核心事实" vs "暂时状态" 的区分 |
| **记忆冲突检测** | ❌ 无 | 新记忆与旧记忆矛盾时无检测和处理 |

**严重程度：中** — 长剧本游戏的核心体验依赖于此，当前能跑但不优雅。

---

## 7. 对话管理

| 能力 | 当前状态 | 差距 |
|------|---------|------|
| **对话分支/回退** | ❌ 无 | 玩家无法 "撤回" 上一句话重新选择 |
| **玩家意图消歧** | ❌ 无 | 模糊输入时 Agent 自己猜，不会反问澄清 |
| **多轮上下文引用** | ⚠️ 基础 | 依赖 LLM 自身理解，无显式的引用追踪 |
| **结构化对话树** | ❌ 无 | 剧本系统只是 .md 文本，非结构化节点 |
| **对话摘要** | ❌ 无 | 无自动生成 "上次发生了什么" 的功能 |

**严重程度：低** — 对于跑团场景影响有限，但撤销功能是 QoL 提升。

---

## 8. 工具系统成熟度

| 能力 | 当前状态 | 差距 |
|------|---------|------|
| **工具超时** | ❌ 无 | 工具执行无超时限制 |
| **工具结果缓存** | ❌ 无 | search_knowledge 相同查询重复调用 |
| **工具组合/管道** | ❌ 无 | 无预定义的工具序列（如 "战斗流程" = attack → damage → state_check） |
| **工具权限控制** | ⚠️ 基础 | NPC Agent 有独立工具集（仅 search_npc_memory），但 GM 工具无细分权限 |
| **工具 Schema 校验** | ⚠️ 依赖 SDK | SDK 提供基础校验，但无业务级校验（如 DC 值合理性） |
| **工具 Mock/测试** | ❌ 无 | 测试时无法模拟工具返回值 |

**严重程度：低** — 当前 13 个工具的基本功能够用。

---

## 9. 多模态

| 能力 | 当前状态 | 差距 |
|------|---------|------|
| **图像生成** | ❌ 无 | 无场景插图、角色立绘生成 |
| **图像理解** | ❌ 无 | 无法识别玩家上传的图片 |
| **语音输入/输出** | ❌ 无 | 纯文本交互 |
| **地图/位置可视化** | ❌ 无 | 无地图系统 |

**严重程度：低** — TRPG 核心体验在文本，多模态是锦上添花。

---

## 10. 生产就绪 (Production Readiness)

| 能力 | 当前状态 | 差距 |
|------|---------|------|
| **鉴权** | ❌ 无 | API 无任何鉴权，任何人可以连接 |
| **限流** | ❌ 无 | 无请求频率限制 |
| **CORS** | ⚠️ 全开 | `allow_origins=["*"]` |
| **健康检查** | ❌ 无 | 无 `/health` 端点 |
| **配置管理** | ⚠️ 基础 | 靠 .env + config.yaml，无环境区分（dev/staging/prod） |
| **容器化** | ❌ 无 | 无 Dockerfile / docker-compose |
| **CI/CD** | ❌ 无 | 无 GitHub Actions 或其他 CI |
| **日志** | ⚠️ 基础 | print/console，无结构化日志、无日志轮转 |

**严重程度：高** — 当前只能本地跑，无法安全地部署到公网。

---

## 11. Agent 推理模式

| 能力 | 当前状态 | 差距 |
|------|---------|------|
| **Chain-of-Thought** | ❌ 隐式 | 依赖 LLM 自身，未在 prompt 中明确要求分步推理 |
| **ReAct 模式** | ❌ 无 | 无 "思考→行动→观察→再思考" 的显式循环 |
| **Self-Reflection** | ❌ 无 | GM 输出后无自检步骤（"我的叙述是否符合设定？"） |
| **Plan-then-Execute** | ❌ 无 | ToolAdvisor 存在但未集成到 process() 流程中 |
| **Multi-Persona Debate** | ❌ 无 | 无多视角验证（如让两个 Agent 辩论某个判断是否正确） |

**严重程度：中** — 加入 reflection 步骤可以显著减少幻觉和逻辑矛盾。

---

## 12. 世界模拟深度

| 能力 | 当前状态 | 差距 |
|------|---------|------|
| **时间推进系统** | ⚠️ 基础 | 只有 time_of_day 字符串，无真实时间轴 |
| **NPC 自主行为** | ⚠️ 基础 | 基于回合触发，非持续模拟 |
| **事件调度** | ❌ 无 | 无 "3 回合后触发某事件" 的调度器 |
| **世界状态扩散** | ❌ 无 | 一个地点的变化不会自动影响相关 NPC |
| **派系/势力系统** | ❌ 无 | 无组织层面的关系网络 |
| **经济/物品系统** | ❌ 无 | 无物品栏、货币、交易 |

**严重程度：低** — 这是产品深度问题，非框架问题。

---

## 优先修复建议

### 🔴 高优先级（安全和稳定）

1. **API 鉴权** — 至少加一个简单的 token/session 机制
2. **game_over 二次确认** — 删档操作需要玩家确认
3. **LLM 重试 + 超时** — 指数退避，30s 超时
4. **Token 用量统计** — 每次请求返回消耗的 token 和费用
5. **结构化日志** — 至少 JSON 格式 + 时间戳

### 🟡 中优先级（体验和质量）

6. **并行 NPC 调用** — 多 NPC 群聊时并发请求
7. **Agent 行为回归测试** — 至少 10 个典型场景的输入-输出验证
8. **记忆自动评分** — LLM 判断 importance，而非硬编码 0.5
9. **CoT/Reflection 步骤** — prompt 中加入 "先思考再行动"
10. **工具结果缓存** — search_knowledge 等幂等查询缓存 1 轮
11. **Docker 化** — 一键部署

### 🟢 低优先级（锦上添花）

12. **对话回退** — 撤销到上一轮
13. **场景插图生成** — 调用图片生成 API
14. **Tracing 集成** — LangSmith / OpenTelemetry
15. **地图可视化** — 前端展示世界地图
