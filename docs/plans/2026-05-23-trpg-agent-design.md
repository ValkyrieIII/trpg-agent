# TRPG Agent 设计说明

## 背景与目标

基于 Claude Agent SDK 开发一个跑团 agent 应用，一天开发时间，优先轻量框架和现成库。核心目标：

- 具有长时记忆和人格化的角色，能与玩家深度互动
- 满足跑团基础机制（骰子、检定、角色属性、事件判定）
- 泛用型/自定义规则，不做特定规则绑定
- CLI 优先，后续可扩展界面

## 现状与约束

- 开发时间：一天
- 技术栈：Python
- LLM：Anthropic SDK (Claude)，已在环境中可用
- 原则：避免 LangChain/LlamaIndex 等重框架，优先零配置库

## 方案对比

### 方案一：纯 prompt 驱动

角色人格、知识、记忆全部写在 prompt 中，每次对话全量注入。

- 优点：实现极简，零外部依赖
- 缺点：上下文膨胀快，记忆无持久化，知识无权限控制

### 方案二：框架全家桶（LangChain + Neo4j + Pinecone）

- 优点：功能完整，社区资源多
- 缺点：一天内学不完，配置运维重，过度工程

### 方案三：轻量混合（推荐，选用）

Anthropic SDK + ChromaDB + NetworkX + Rich CLI，分层清晰，各组件独立。

- 优点：每层都是最轻选择，pip install 即用，调试简单
- 缺点：需要手动组装管线，无现成抽象

## 推荐方案

方案三：轻量混合架构，每个组件只做一件事，组合完成复杂任务。

### 关键组件

**框架选型：**

| 层 | 选型 | 理由 |
|---|------|------|
| LLM | Anthropic SDK (Claude) | 已在环境中，零额外配置 |
| 向量库 | ChromaDB | pip install，零配置 |
| 图关系 | NetworkX | 纯 Python，遍历 API 简单 |
| Embedding | sentence-transformers (all-MiniLM-L6-v2) | 本地跑，不花钱 |
| 记忆持久化 | SQLite + JSON | 标准库 |
| CLI | Rich | 一个 pip install |

```bash
pip install chromadb networkx sentence-transformers rich anthropic pyyaml
```

**项目结构：**
```
trpg-agent/
```

### 角色系统

角色卡结构（config.yaml）：

```yaml
character:
  name: "艾琳"
  core:
    - "你叫艾琳，北方荒原的游侠"
    - "曾独自在荒野生存十年"
  
  personality:           # 说话方式层
    tone: "短句，直接，偶尔冷幽默"
    verbal_tics: "紧张时重复主语"
    emotion_map:          # 情感 → 行为映射
      anger: "压低声音，语速变慢"
      fear: "过度警觉，反问句增多"
      trust: "话变多，偶尔流露脆弱"
    catchphrases:
      - "荒野教过我：..."
  
  few_shot:              # 3-5 条对话示例
    - { input: "你好", output: "嗯，活着就好。" }

  attributes:
    strength: 14
    agility: 18
    intelligence: 12
    willpower: 15

  skills:
    - { name: "追踪", value: 75 }
    - { name: "弓箭", value: 80 }
    - { name: "野外生存", value: 90 }
```

每轮 prompt 组装：

```
[系统] 人格（core + personality + few_shot — 全量注入）
[当前状态] 情绪 + 信任 + 体力
[RAG 检索] 按角色身份过滤后注入
[记忆检索] 语义检索 + 图遍历关联记忆
[历史] 最近 N 轮对话（滑动窗口，超出摘要压缩）
```

人格全量注入（~300-500 token），不拆分检索，避免检索漏检导致角色扁平。

### 状态机

精简 3 维度，规则驱动（不调 LLM）：

| 维度 | 范围 | 触发示例 |
|------|------|---------|
| 情绪 | calm → wary → hostile | 玩家失信 → +1 |
| 信任 | 0.0 ~ 1.0 | 完成任务 → +0.1 |
| 体力 | fresh → tired → exhausted | 战斗/长途 → -1 |

状态影响角色说话方式（emotion_map），但不主导。

### 骰子与检定系统

**骰子表达式：** d20 / d100 / ndm+k

**检定类型：**
- 技能检定：d100 ≤ skill_value → 成功
- 对抗检定：双方 d20 + 修正，比大小
- 难度检定：d20 vs DC（5/10/15/20）

### 记忆系统

**混合存储：** ChromaDB（语义检索） + NetworkX（图关系）

**记忆条目结构：**
```
├── id, content, type (event/fact/emotion_peak)
├── timestamp, importance (0-1), tags
└── context: { location, npcs, emotion }
```

**图关系类型：** "导致了" / "关联到" / "反驳了" / "发生在...之后"

**检索流程：**
```
玩家输入
  → ChromaDB 语义检索匹配记忆
  → NetworkX 沿图 1-2 跳遍历关联记忆
  → 按 importance 排序，拼接为叙事摘要
  → 注入 prompt
```

**写入触发：**
- 每轮对话后自动记录（type: event）
- 重要信息抽取（NPC 名字、地点、关键决策 → type: fact）
- 情绪峰值检测（状态机情绪突变 → type: emotion_peak）

关键事件抽取由一次轻量 LLM 调用完成。

### RAG 知识库

存储世界观设定、剧本背景、NPC 简介——角色"应该知道但不一定记住"的信息。

**源文件：** `data/knowledge/` 下 markdown 文件，启动时加载到 ChromaDB。

**权限控制：标签过滤**

每条知识标注 `known_by`：
```yaml
- content: "酒馆地下有一条密道通往郊外"
  known_by: ["酒馆老板", "老酒客"]
- content: "镇上每年冬至举行祭祀"
  known_by: "所有人"
```

检索时按 `当前角色名` 或 `所有人` 过滤，只返回角色应该知道的信息。

**置信度阈值：** 语义检索相似度低于阈值的不注入，避免角色"知道"无关信息。

### 数据流：一轮对话

```
玩家输入
    │
    ▼
┌─ GM ──────────────────────────────────────────┐
│ 1. 意图识别（正则匹配，不调 LLM）                │
│    → "dice" / "info" / "combat_check" / "dialogue"
│                                                │
│   如果是对话：                                  │
│   2. 检索                                      │
│      ├ ChromaDB 语义搜记忆 → NetworkX 图遍历    │
│      └ ChromaDB RAG 搜知识（按角色过滤）        │
│                                                │
│   3. 组装 prompt                               │
│      [人格] 角色卡 + few-shot                   │
│      [状态] 情绪/信任/体力                      │
│      [知识] RAG 检索结果                        │
│      [记忆] 关联记忆摘要                        │
│      [历史] 最近 N 轮对话                       │
│                                                │
│   4. Claude 生成回复                            │
│                                                │
│   5. 状态机更新                                 │
│                                                │
│   6. LLM 抽取事件 → 写入记忆（ChromaDB + 图）    │
└────────────────────────────────────────────────┘
```

规则操作（掷骰/查看属性）走单独的检定管线，不调 LLM。

### 异常与边界处理

- **LLM 超时/失败：** 重试一次，失败后提示玩家
- **检索无结果：** 记忆/知识缺失时不强塞，标注"无相关信息"
- **角色卡未配置：** 启动时校验必填字段，缺少时给出明确错误
- **对话历史溢出：** 滑动窗口 + 摘要压缩，超过 N 轮自动归档为记忆
- **输入为空：** 提示玩家输入有效内容

### 测试策略

| 层 | 测什么 | 工具 |
|---|--------|------|
| 骰子 | 表达式解析 + 范围验证 | pytest（必测） |
| 检定 | d20/d100/对抗判定逻辑 | pytest（必测） |
| 状态机 | 情绪/信任/体力转换规则 | pytest（必测） |
| 记忆 | 写入 → 检索来回一致性 | pytest |
| 完整对话 | 端到端一轮对话 | 手动 smoke |
| RAG 检索 | 写入数据 → 检索验证 | 手动 smoke |

原则：确定性逻辑必测，LLM 输出手动验证。

## 风险与待确认项

- sentence-transformers 模型首次下载需网络（all-MiniLM-L6-v2 约 80MB）
- 一天开发时间紧张，多轮对话调试可能需要额外时间
- 状态转换规则需要实际跑团中调优，初始值基于经验预设
